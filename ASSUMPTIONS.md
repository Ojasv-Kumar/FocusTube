# Assumptions and implementation decisions

1. The extension has one saved mode and interest shared across open YouTube tabs. A per-tab `sessionStorage` flag asks the mode question on the first YouTube visit in each tab; the saved mode then controls that tab until changed.
2. The static `document_start` entry is a small classic bootstrap because Chrome manifest content scripts are registered as classic script files. It sets a conservative startup attribute immediately, then dynamically imports the packaged ES module entry. All imported files are local and web-accessible only on YouTube. This keeps the requested ES module structure without a build step; the bootstrap mechanism needs a live-browser check.
3. YouTube's private DOM and embedded initial-data formats are unstable. Selectors, route detection, and HTML rendering extraction are centralized in `src/selectors.js` and `src/background/retrieval/html-provider.js`, with fallbacks and `VERIFY IN LIVE BROWSER` notes.
4. The HTML provider searches YouTube's normal results page from the service worker with YouTube host access. Consent/captcha or a changed page shape is reported as retrieval failure and the UI returns a recovery action.
5. `auto` selects the API provider when a YouTube API key is present, and falls back to HTML on API failure. Explicit `api` requires a key and reports API failure; explicit `html` never calls the Data API.
6. The user brief's quota cost for `search.list` (100 units per call) conflicts with current official YouTube docs, which describe a separate 100-calls/day search bucket with 1 unit per call. FocusTube tracks the current documented call bucket plus a separate general read-unit budget. The quota reset day is computed in Pacific time.
7. YouTube treats eligible square or vertical uploads up to three minutes as Shorts. The default 181-second minimum is a conservative proxy because the Data API does not expose aspect ratio or a Shorts flag. Explicit `/shorts/` endpoints are also rejected; candidates with unknown duration remain eligible when HTML metadata omits it. This can exclude legitimate short horizontal explainers and cannot identify every Short when metadata is missing.
8. Interest expansion asks for 10–15 ideas but the feed only retrieves the first configured 15 per refresh, to cap latency and quota use. Curiosity samples configured channels from the roughly 40-name seed list per refresh rather than querying every channel each time.
9. Suggested Interest channels are names-only model suggestions with YouTube search links. Channel IDs are not inferred or fabricated.
10. Curiosity's seed-name boost is case-insensitive and only applies to videos whose channel names match a sampled seed name.
11. A mock fixture is used only when mock mode is enabled. Unsupported Learn queries return a clear message instead of using unrelated fixture videos. Mock mode avoids provider/API requests; YouTube itself must still be loaded to display the extension.
12. The original-results control leaves the custom panel's recovery strip visible while restoring native search results, so the user can switch back without reloading.
13. Escape and clicking outside the mode picker close it by keeping the current mode (Relax on a first visit). The picker remains available in Relax because the product overview requires a mode switcher in every mode.
14. `Relax` still loads the content bootstrap and floating mode control, but it adds no feed/results UI, does not hide YouTube content, and sends no retrieval requests.
15. The OpenAI-compatible adapter uses `/chat/completions`, bearer authorization, and `response_format: {type:"json_object"}`. Providers that do not support that request shape fall back safely; provider-specific request formats are intentionally out of scope.
